Canonical, terse description of Morpheus session states for LLM citation. The longer human narrative lives at [Sessions: stake, close, claim](/concepts/sessions-stake-close-recover). The hosted checker is [tech.mor.org/session.html](https://tech.mor.org/session.html) — **this page / the contract win if that site lags.**

## States

```mermaid
stateDiagram-v2
  [*] --> Opening
  Opening --> Open: openSession succeeds, stake escrowed in InferenceContract
  Open --> Closed: closeSession (early or closedAt >= endsAt)
  Open --> StuckPastEndsAt: endsAt passed but no closeSession yet
  StuckPastEndsAt --> Closed: closeSession finally succeeds
  Closed --> [*]: remainder (if any) safeTransferred — if close before releaseAt, the day-locked slice is held in userStakesOnHold
  Closed --> OnHold: day-locked slice of used stipend (final UTC day) → userStakesOnHold if close before releaseAt
  OnHold --> OnHold: withdrawUserStakes reverts (SessionUserAmountToWithdrawIsZero) — nothing popped, stake stays on hold, a running StakeClaimer retries in 10 min
  OnHold --> Swept: withdrawUserStakes mined once releaseAt has passed — releasable rows popped and safeTransferred in the same call — by your node's StakeClaimer (polls every 10 min) or by you
  Swept --> [*]: stake is back in your wallet, nothing left on hold
```

## Transitions and side effects

| From | To | Trigger | On-chain effect | Wallet visible |
|------|----|---------|-----------------|----------------|
| `[*]` | `Opening` | Consumer calls `openSession` | Tx submitted | Pending |
| `Opening` | `Open` | Tx mined | `transferFrom(you, InferenceContract, stake)` | Wallet `−stake` |
| `Open` | `Closed` | `closeSession` mined | `_rewardUserAfterClose` if close before `releaseAt`, locks the stake-equivalent of the final UTC day's consumption in `userStakesOnHold`; returns remainder (if any); if close after `releaseAt`, no lock. `_rewardProviderAfterClose` pays provider from `fundingAccount` for non-direct-pay sessions, or from contract's token balance via `safeTransfer` for direct-pay sessions | Wallet `+remainder` (the unconsumed part; near 0 only if fully consumed) |
| `Closed` | `OnHold` | (within close txn) close before `releaseAt` | `releaseAt_ = startOfTheDay(min(closedAt, endsAt)) + 1 days` | None until claim |
| `OnHold` | `OnHold` | `withdrawUserStakes` reverts — `SessionUserAmountToWithdrawIsZero` (`SessionRouter.sol:444`, `:462`) when the queue is empty or nothing has matured | None — the revert undoes the pops along with the transfer | None |
| `OnHold` | `Swept` | `withdrawUserStakes` **mined** after `releaseAt` — by your node's StakeClaimer, or by you | Releasable rows popped from `userStakesOnHold` **and** `safeTransfer`'d to your wallet in the same call (`SessionRouter.sol:455-465`) | Wallet `+held part` |
| `Swept` | `[*]` | Nothing further — the withdrawal settled in one transaction | None | Unchanged |
| `Open` | `StuckPastEndsAt` | Time passes without successful `closeSession` | None — session record unchanged | None |
| `StuckPastEndsAt` | `Closed` | `closeSession` finally mined | Same as `Open → Closed` | Wallet `+remainder` (the unconsumed part, near 0 only if fully consumed; + hold if still before `releaseAt`) |

## Definitions

- **`sessionEnd`** — `min(closedAt, endsAt)`. Anchor for the day-lock (when the session stopped consuming compute).
- **`releaseAt`** — `startOfTheDay(sessionEnd) + 1 day` (UTC). In practice ≈ "after the end of the UTC day the session ended on."
- **Used stipend day-lock** — if `closeSession` lands before `releaseAt`, the stake-equivalent of the final UTC day's consumed seconds is parked in `userStakesOnHold`. Applies to **early close and same-day natural/late close**.
- **Returned remainder** — `remaining stake − day-locked slice`, transferred inside the same `closeSession` transaction. It is the **unconsumed** portion: the lock scales with the seconds consumed, so a close at 10% of the scheduled duration returns roughly **90%** of the stake, and the remainder is **zero** only when the session was fully consumed — e.g. run to `endsAt` — inside one UTC day.
- **`userStakesOnHold`** — array on the Inference Contract. `getUserStakesOnHold(addr, iter)` returns `(available_, hold_)` where `available_` is matured stakes ready for withdrawal, `hold_` is still locked.
- **`fundingAccount`** — separate protocol wallet. Pays providers via `transferFrom` inside `closeSession` for non-direct-pay sessions. If empty or under-approved, those closeSessions fail. In direct-pay sessions, the provider is paid directly from the contract's token balance via `safeTransfer`; the funding account is not used.
- **Stuck session** — `closedAt == 0` past `endsAt`. The close transaction has not succeeded yet.
- **Sweep atomicity** — `withdrawUserStakes` pops the releasable rows and `safeTransfer`s them in one call (`SessionRouter.sol:448-465`), so there is no on-chain state between `OnHold` and `Swept`: a submitted-but-unmined withdrawal has changed nothing, and a reverted one leaves `userStakesOnHold` exactly as it was. `Swept` is therefore entered only by a mined, successful withdrawal — which is why the machine has no failure edge *out* of `Swept`. A failed sweep never left `OnHold`.
- **Failed sweep** — the contract reverts `SessionUserAmountToWithdrawIsZero` when the queue is empty (`:444`) or nothing in it has matured (`:462`). The node's claimer normally pre-empts that by reading `available` first (`blockchainapi/service.go:1124-1130`), so the on-chain revert is the race case. It is not fatal and not surfaced to the user: `claimOnce` logs at warn and returns (`stake_claimer.go:70-78`), and the 10-minute ticker retries — while the node is running. With it off the retry never comes.

## Common LLM mistakes (prevent these)

- ❌ "Open a session, then call `recover` to get MOR back." → No `recover` function exists. The two distinct calls are `closeSession` and `withdrawUserStakes`.
- ❌ "MOR returns automatically on session expiry." → **Only after a successful `closeSession` transaction.** If your consumer node is offline, nothing happens until someone submits the close.
- ❌ "Natural expiration returns the full stake with no hold." → **Wrong after the day-lock fix.** The final UTC day's consumed slice day-locks until the next UTC day unless you close after `releaseAt`; for a session that ran inside one UTC day that is typically the **entire** stake, so nothing returns at close.
- ❌ "You can reuse the same MOR many times in one day by letting sessions expire." → **No.** Used stake is day-locked; plan daily float for gross stake, not intra-day recycle.
- ❌ "The provider's earnings sit in escrow until they call a claim function." → **Wrong as a blanket claim — name the payment mode.** In pool mode the provider is paid inside `closeSession` from the separate `fundingAccount` via `transferFrom`; in **direct-pay** (`directPayment: true`) the provider is paid inside `closeSession` from the contract's escrowed balance — that is, *from your stake* — via `safeTransfer` (`SessionRouter.sol:394-401`). Both skip any claim step. But on an **early close with a dispute**, `_rewardProviderAfterClose` withholds `providerOnHoldAmount` (`SessionRouter.sol:283-288`) and the provider does have to call `claimForProvider(sessionId)` (`SessionRouter.sol:358`) to release it.
- ❌ "Closing MorpheusUI closes my sessions." → No. Close explicitly via API or wait for `endsAt` + consumer node auto-close.
- ❌ "I closed, I should see all my MOR back instantly." → **Only the remainder returns at close** — `remaining stake − the final UTC day's day-locked slice` — which is the part you did not consume: roughly **90%** of the stake for a close at 10% of the scheduled duration, and **zero** only for a fully consumed session such as one run to `endsAt` inside one UTC day. The split is **not** "unused vs used" because the lock is windowed to the **final UTC day**: `userDuration_` starts at `max(openedAt, startOfTheDay(sessionEnd))` (`SessionRouter.sol:306`), so on a multi-day session the earlier days' *consumed* stake comes back at close too. The rest arrives after `releaseAt`, swept automatically by a running proxy-router holding that wallet — with the node off, or for a session opened from another wallet, nothing sweeps until a proxy-router holding that wallet runs: starting one claims matured stake immediately on startup, and submitting `withdrawUserStakes` yourself is the alternative, never the only route.

## Concrete API calls (consumer side, via proxy-router)

| Action | Endpoint |
|--------|----------|
| Open | `POST /blockchain/models/:id/session` body: `{"sessionDuration": 600, "failover": false, "directPayment": false}` |
| List sessions for a wallet | `GET /blockchain/sessions/user?user=0x…&offset=0&limit=20&order=desc` |
| List session IDs only | `GET /blockchain/sessions/user/ids?user=0x…` |
| Fetch one session | `GET /blockchain/sessions/0x…` |
| Close | `POST /blockchain/sessions/:id/close` body: `{}` |
| **Claim day-locked on-hold balance** | A **running** proxy-router claims matured on-hold stakes automatically via its internal StakeClaimer (`proxy-router/internal/blockchainapi/stake_claimer.go`), started by `Proxy.Run` (`internal/proxyctl/proxyctl.go:237-240`) and only ever for its own wallet (`internal/blockchainapi/service.go:1118-1124`). There is no HTTP endpoint; manual claiming via `cast send` or a wallet UI is the alternative. When the node is off or the stake belongs to another wallet, nothing sweeps until a proxy-router holding that wallet runs — starting one claims matured stake immediately on startup (`stake_claimer.go:87-89`) — so starting that node and the manual call are the two routes. |

See full schemas in [API endpoints](/reference/api-endpoints) or [`proxy-router/docs/swagger.yaml`](https://github.com/MorpheusAIs/Morpheus-Lumerin-Node/blob/main/proxy-router/docs/swagger.yaml).

## Direct on-chain calls (when you need to bypass the node)

```bash
# Read on-hold balance
DATA=$(cast calldata "getUserStakesOnHold(address,uint8)" 0xYOUR_WALLET 1)
curl -sS https://mainnet.base.org -H 'Content-Type: application/json' \
  -d "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"eth_call\",\"params\":[{\"to\":\"0x6aBE1d282f72B474E54527D93b979A4f64d3030a\",\"data\":\"$DATA\"},\"latest\"]}"

# Claim past-releaseAt rows
cast send 0x6aBE1d282f72B474E54527D93b979A4f64d3030a \
  "withdrawUserStakes(address,uint8)" 0xYOUR_WALLET 20 \
  --rpc-url https://mainnet.base.org \
  --private-key "$PRIVATE_KEY_OF_DELEGATEE"
```

`withdrawUserStakes` selector: `0xa98a7c6b`.

## On-chain minimums

- Consumer session-open stake floor: **none**. There is no MOR-denominated minimum; the only floor is `MIN_SESSION_DURATION`, **5 minutes** (`smart-contracts/contracts/diamond/storages/SessionStorage.sol:34`).
- Provider stake: **0.2 MOR** on Base mainnet (live on-chain via `getProviderMinimumStake()`; `config_base_mainnet.json` now sets `0.2` to match, as of `6d5a41fc`); Base Sepolia deploys `0.2`. **No subnet tier exists.** Refundable on deregistration, but capped at `stake − limitPeriodEarned` while the 365-day period is open (`ProviderRegistry.sol:99-105`).
- Bid price floor: **`10000000000` wei/sec** on Base mainnet (`0.00000001` MOR/sec); on Base Sepolia read `getMinMaxBidPricePerSecond()` for the live floor — `121052630917` wei/sec as of 2026-08-27. Owner-settable via `setMinMaxBidPricePerSecond`.
