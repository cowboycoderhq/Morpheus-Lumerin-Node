The single most important rule: **MorpheusUI / Swagger / CLI all depend on a healthy proxy-router**. If the proxy-router is wedged or can't talk to the BASE node, none of the higher layers will work.

Tip: run the proxy-router in a foreground terminal at least once so you can see startup logs in real time. For log destinations and verbosity, see the **Logging Configuration** section of [`docs/proxy-router.all.env`](https://github.com/MorpheusAIs/Morpheus-Lumerin-Node/blob/main/docs/proxy-router.all.env).

## Healthy startup looks like

```
INFO  proxy state: running
INFO  HTTP  http server is listening: 0.0.0.0:8082
INFO  TCP   tcp server is listening: 0.0.0.0:3333
```

You can also confirm via `http://localhost:8082/swagger/index.html` (or whatever URL is set in your `.env`).

## Proxy-router is not starting / crashing immediately

### Likely cause 1: `.env` misconfiguration

These four values **must** match your chain and OS. Use `proxy-router/.env.example` as the canonical reference (there is no `env.main.example`; Windows has `.env.example.win`):

- `DIAMOND_CONTRACT_ADDRESS=`
- `MOR_TOKEN_ADDRESS=`
- `BLOCKSCOUT_API_URL=`
- `ETH_NODE_CHAIN_ID=`
- `PROXY_STORAGE_PATH=./data/badger/` (or omit; default is `./data/badger/`)

If running the proxy-router headless (without the UI), set:

- `WALLET_PRIVATE_KEY=` — the provider's wallet private key.

If you bring your own ETH node (Alchemy, Infura, etc.):

- Confirm `ETH_NODE_ADDRESS=` is correct for the chain (`proxy-router/internal/config/config.go:29`). There is no `ETH_NODE_URL` variable.
- Recommended: HTTPS over WSS, with `ETH_NODE_USE_SUBSCRIPTIONS=false`.

Full reference: [Env: proxy-router](/reference/env-proxy-router).

### Likely cause 2: the ETH node or contract addresses are unreachable

This is the most common startup abort in practice (`main.go:242-254`). A wrong
`ETH_NODE_ADDRESS`, an unreachable RPC, or an `ETH_NODE_CHAIN_ID` that disagrees
with the node's own chain ID all exit non-zero with `cannot connect to ethereum node`.

Earlier aborts, in the order `main.go` reaches them, if the log stops before the
RPC lines: `SYS_ENABLE=true` with insufficient privileges (`:146-149`), a
`PROXY_STORAGE_PATH` that cannot be created or opened (`:204-207`), an
unparseable `proxy.conf` (`:217-219`), and a `COOKIE_CONTENT` without a `:`
separator (`:222-224`). If the log stops even earlier than those and the exit
status is **0**, it is not an abort at all — see the next section.

### Not a crash: exits 0 immediately, nothing listening

If the process ends straight away with **no error output and exit code 0**, check
`APP_RESET_KEYCHAIN`. Set `true` it is a one-shot maintenance wipe, not a startup
modifier: `proxy-router/cmd/main.go:181-199` deletes the stored wallet and the
stored ETH-node URLs and then returns `nil` before any of the node exists —
storage, the RPC client and the HTTP server all start at `:204` — so
`proxy-router/cmd/main.go:47-53` exits 0. Nothing listens on `:8082` or `:3333`,
and because the exit is clean, a Docker `restart:` policy, a systemd unit or a
Kubernetes probe reads it as a successful run rather than a failure. Unset the
variable (or set it `false`) and restart. It is also not macOS-specific: the
keychain lane uses `go-keyring`, which ships macOS, Windows and Linux/BSD
backends, and `proxy-router/cmd/main.go` has no platform guard.

### Not a cause: `models-config.json`

A missing, unreadable, or malformed `models-config.json` does **not** stop the
proxy-router. `ModelConfigLoader.Init` returns an error, and `main.go:311-315`
logs `failed to load model config, running with empty` at warn level and
continues — the node starts, answers `/healthcheck`, and serves **zero models**.
The same is true of `agents-config.json` (`main.go:317-321`). So if your node is
crash-looping, the models config is the wrong place to look; and if it is running
but no one can open a session against you, this is exactly what that looks like.
Check the `models` array in `GET /healthcheck`, not the exit code.

### Resolution

1. Fix `.env` — chain values first, then `ETH_NODE_ADDRESS`.
2. Restart the proxy-router.
3. Watch the log for connection errors to the ETH node and the Diamond contract.
4. Once it stays up, confirm the model set separately (see above) — startup
   succeeding says nothing about `models-config.json` having loaded.

## Wallet shows zero MOR / ETH after recovering from mnemonic

You probably selected a different **derived account**. The import flow lets you pick any of 10 accounts derived from the mnemonic (`ImportFlow.jsx:113`) — check you chose the one holding your funds. Either:

- Use a wallet that was originally created from this mnemonic at index 0, or
- Import the **private key** directly instead of the mnemonic.

## Local model returns nonsense

The bundled `Qwen2.5-1.5B-Instruct` is a **demo** model — 1.5B parameters, chosen to be small enough to ship rather than to be good. Compare quality only against real Morpheus models. See [Local vs on-chain models](/concepts/local-vs-onchain-models).

## Provider-side: consumers can't connect

- Confirm `:3333` is **publicly reachable** (`telnet host 3333` from outside your network).
- Confirm `WEB_PUBLIC_URL` and the registered provider `endpoint` match your actual public host.
- Inspect provider logs — connection attempts and rejections show up there.

---

## Provider-side: TEE attestation fails on the consumer

- Confirm your model is registered with the `tee` tag.
- Confirm the consumer is on `v6.0.0+` (Phase 1) — Phase 2 benefits are provided transparently by the v7+ provider; no consumer upgrade is required.
- Recheck the SecretVM portal at https://secretai.scrtlabs.com/attestation with your compose and VM URL — all three layers must pass.
- Use `cosign verify` and `cosign verify-attestation` on your `-tee` image. See [TEE reference](/providers/full/tee-reference).

## "Locked files" or stale processes after Ctrl+C

- macOS / Linux:
  ```bash
  ps -ax | grep proxy-router
  kill -9 <pid>

  lsof | grep /proxy-router/data/
  kill -9 <pid>
  ```
- For Electron / MorpheusUI: `ps -ax | grep electron` and kill stragglers.

See also: [Consumer troubleshooting](/consumers/troubleshooting).
