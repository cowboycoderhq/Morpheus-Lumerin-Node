This page gives prose context for the endpoints integrators reach for first when calling **the proxy-router HTTP API** (i.e. the API your local node exposes on `:8082`). The generated schema lives at [`proxy-router/docs/swagger.yaml`](https://github.com/MorpheusAIs/Morpheus-Lumerin-Node/blob/main/proxy-router/docs/swagger.yaml) and is browsable at `http://localhost:8082/swagger/index.html` when your node is running. It is generated from the handler annotations and currently carries an entry for every route the server registers — see [Full schema](#full-schema) for what keeps it that way.

<Note>
If you're looking for the **hosted** OpenAI-compatible Morpheus product (no node required), that is a separate service — see [Inference API overview](/inference-api/overview) and [apidocs.mor.org](https://apidocs.mor.org).
</Note>

## Authentication

Nearly all endpoints require **Basic Authentication**:

```
Authorization: Basic <base64(username:password)>
```

<Warning>
**Five routes are served without authentication.** Each is registered with no
`CheckAuth` middleware, and the global auth middleware in
`proxy-router/internal/handlers/httphandlers/http.go:67-85` is commented out:

| Route | Registered at |
|---|---|
| `GET /healthcheck` | `internal/system/controller.go:67` |
| `POST /proxy/provider/ping` | `internal/proxyapi/controller_http.go:88` |
| `POST /auth/users/request` | `internal/authapi/controller_http.go:35` |
| `GET /auth/cookie/path` | `internal/authapi/controller_http.go:45` |
| `GET /swagger/*any` | `internal/handlers/httphandlers/http.go:64` |

`GET /auth/cookie/path` returns the filesystem path of the admin credential file.
Treat the proxy-router's listen address as trusted-network-only; do not expose it
to the public internet on the assumption that Basic Auth covers every route.
</Warning>

See [API auth](/reference/api-auth).

## Chat completions

`POST /v1/chat/completions`

OpenAI-compatible chat. The request body is forwarded to the provider; you don't need a `model` field — it's set by the provider based on `session_id`.

| Header | Purpose |
|--------|---------|
| `session_id` (hex32) | Required for remote provider routing |

```bash
curl --location 'http://localhost:8082/v1/chat/completions' \
  --header 'Accept: application/json' \
  --header 'session_id: 0x8e12df2f764b416c0ea1936a253c2a4be01005651c2d73f22dd0d72520f93ca1' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Basic YWRtaW46YWRtaW4=' \
  --data '{
    "messages": [
      {"role": "system", "content": "You are a helpful assistant."},
      {"role": "user", "content": "Tell me about AI."}
    ],
    "stream": false,
    "max_tokens": 2048
  }'
```

Response: `200 OK`, `text/event-stream` (streaming) or `application/json`.

## Audio transcriptions

`POST /v1/audio/transcriptions`

`multipart/form-data`. The body is forwarded — any field the provider accepts will pass through. Common fields:

| Field | Notes |
|-------|-------|
| `file` | Audio file |
| `s3_presigned_url` | Pre-signed URL for secure file access |
| `language` | |
| `response_format` | `json` / `text` / `srt` / `verbose_json` / `vtt` |
| `timestamp_granularities[]` | `word` / `segment` |
| `output_content` | |
| `enable_diarization` | Boolean |

```bash
curl --location 'http://localhost:8082/v1/audio/transcriptions' \
  --header 'session_id: 0x9fe60aa88c4e8d44414431dd565353efb762a923d639f54f856b3ac657e16263' \
  --header 'Authorization: Basic YWRtaW46YWRtaW4=' \
  --form 'file=@"/path/to/harvard.wav"'
```

## Audio speech (TTS)

`POST /v1/audio/speech`

JSON. Common fields: `input` (required), `voice`, `response_format` (`mp3`/`opus`/`aac`/`flac`/`wav`/`pcm`; default `mp3`), `speed`.

```bash

  --header 'Authorization: Basic YWRtaW46YWRtaW4=' \
  --data '{"input": "Lorem ipsum dolor sit amet.", "voice": "af_alloy"}'
```

## Close session

`POST /blockchain/sessions/:id/close`

```bash
curl --location 'http://localhost:8082/blockchain/sessions/0xf343b654cc8a21d0666c38606146ae68ef67b4445643deba02991a72f0d09785/close' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Basic YWRtaW46YWRtaW4=' \
  --data '{}'
```

Response includes the on-chain transaction hash.

**Note on refunds:** the refund is `remaining stake − the day-locked slice`, not "unused stake" — the lock is sized from the **final UTC day's** consumption, so a multi-day session gets earlier days' *consumed* stake back at close too, while a session left to run to `endsAt` inside one UTC day is fully consumed and returns approximately **nothing** — the lock scales with the seconds consumed, so it equals the whole remaining stake only as consumption approaches the full scheduled duration, not because the session was same-day. An early close returns the unconsumed part: roughly 90% of the stake at 10% of the scheduled duration. Whatever is left is `safeTransfer`'d back in this same transaction. The **final UTC day's consumed slice** may be parked in `userStakesOnHold` with `releaseAt = startOfTheDay(min(closedAt, endsAt)) + 1 day` — including same-day natural/late close. A running proxy-router's StakeClaimer automatically sweeps matured stakes for the wallet it holds, so manual `withdrawUserStakes` is not required — with the node off, or for stakes belonging to a different wallet, nothing sweeps until a proxy-router holding that wallet runs: starting one claims matured stake immediately on startup, and the manual call is the alternative. Use `GET /blockchain/stakes/on-hold` to check the balance. See [Sessions: stake, close, claim](/concepts/sessions-stake-close-recover).

## List sessions for a wallet

`GET /blockchain/sessions/user?user=0x…&offset=0&limit=20&order=desc`

```bash
curl --location -u 'admin:admin' \
  'http://localhost:8082/blockchain/sessions/user?user=0xYOUR_WALLET&offset=0&limit=20&order=desc'
```

Variant for IDs only: `GET /blockchain/sessions/user/ids?user=0x…`. Fetch one: `GET /blockchain/sessions/0x<sessionId>`.

## Claim day-locked on-hold balance (no node HTTP route)

A running proxy-router claims matured on-hold stakes automatically via its internal StakeClaimer (see `proxy-router/internal/blockchainapi/stake_claimer.go`). That is bounded twice: the claimer is started only inside `Proxy.Run` (`internal/proxyctl/proxyctl.go:237-240`), and it withdraws only for the node's own `GetMyAddress` (`internal/blockchainapi/service.go:1118-1124`). With the node stopped, or for stakes belonging to a different wallet, nothing is claimed. There is no dedicated HTTP endpoint, so manual claiming via `cast send` or a wallet UI is the alternative for direct contract interaction. In those two cases nothing sweeps until a proxy-router holding that wallet runs — starting one claims matured stake immediately on startup (`stake_claimer.go:87-89` calls `claimOnce` before entering the ticker loop) — so starting that node and the manual call are the two routes.

```bash
cast send 0x6aBE1d282f72B474E54527D93b979A4f64d3030a \
  "withdrawUserStakes(address,uint8)" 0xYOUR_WALLET 20 \
  --rpc-url https://mainnet.base.org \
  --private-key "$PRIVATE_KEY_OF_DELEGATEE"
```

Function selector: `0xa98a7c6b`. The caller must be the delegatee allowed for that consumer (usually the same key your consumer node uses). `iterations_` (e.g. `20`) caps how many releasable on-hold rows to process per call. Read on-hold balance via `getUserStakesOnHold(addr, iterations_)` — see [Where is my MOR? → Bucket 2](/ai/where-is-my-mor#bucket-2-on-hold-queue-used-stipend-day-lock).

## Full schema

The generated OpenAPI schema lives at [`proxy-router/docs/swagger.yaml`](https://github.com/MorpheusAIs/Morpheus-Lumerin-Node/blob/main/proxy-router/docs/swagger.yaml). When your proxy-router is running, the same spec is browsable interactively at `http://localhost:8082/swagger/index.html`.

That committed file is generated from the godoc annotations on the handlers by `swag init`, and it is **current**: every route the proxy-router registers has a spec entry with a summary. The only registration with no operation in the spec is `GET /swagger/*any` (`internal/handlers/httphandlers/http.go:64`), the gin catch-all that serves the Swagger UI itself rather than an API operation. The spec's auth surface matches the registrations too: the only operations without a `security` block are the other four unauthenticated routes listed under [Authentication](#authentication) above.

Regeneration is still a manual `cd proxy-router && make swagger`, but forgetting it no longer ships a stale spec. The `spec-fresh` job in `.github/workflows/proxy-router-ci.yml:254-278` runs `scripts/check-spec-fresh.sh`, which lifts the real `swag init` line out of `make -n swagger`, regenerates into a scratch directory and compares `docs.go`, `swagger.json` and `swagger.yaml` byte-for-byte, failing the build on any difference. It is guarded by `github.repository == 'cowboycoderhq/Morpheus-Lumerin-Node'`, so it fails the build in this repository and on pull requests opened against it, and is skipped rather than reported green on anyone else's fork (see [API overview](/reference/api-overview#where-the-schema-lives)). Where a route registration and the spec ever do disagree, the registration is upstream of the spec and wins.
