The proxy-router exposes an OpenAI-compatible HTTP API plus Morpheus-specific routes for blockchain operations and node management.

## Surface

This page documents the **proxy-router HTTP API** — the local API exposed by the proxy-router binary in this repo. It is **not** the hosted Morpheus Inference API; that is a separate product at [apidocs.mor.org](https://apidocs.mor.org), described in [Inference API overview](/inference-api/overview).

| Surface | URL (default) | Purpose |
|---------|---------------|---------|
| Local API | `http://localhost:8082` | Nearly all proxy-router HTTP endpoints (auth-protected; exceptions: /healthcheck, /proxy/provider/ping, /auth/users/request, /auth/cookie/path, /swagger/*any) |
| Swagger UI | `http://localhost:8082/swagger/index.html` | Interactive request playground served by your own proxy-router |
| Public proxy | `tcp://<host>:3333` | TCP tunnel for consumer ↔ provider sessions |
| TEE attestation | `https://<host>:21434` (host-net Caddy) or `https://<host>:29343` (attest-rest) | TDX attestation (`/cpu`, `/gpu`, `/docker-compose`) |

## Authentication

Nearly all endpoints require **HTTP Basic Auth**; however, five specific routes—/healthcheck, /proxy/provider/ping, /auth/users/request, /auth/cookie/path, and /swagger/*any—are served without authentication:

```
Authorization: Basic <base64(username:password)>
```

The `.cookie` file in your proxy-router directory has the default `admin:<random>`. Add scoped users via `proxy.conf` and the `/auth/users` endpoints. Full reference: [API auth](/reference/api-auth).

## Where the schema lives

The canonical OpenAPI schema for the proxy-router HTTP API is [`proxy-router/docs/swagger.yaml`](https://github.com/MorpheusAIs/Morpheus-Lumerin-Node/blob/main/proxy-router/docs/swagger.yaml) — a file committed to the repository, not a build artifact. No build step regenerates it: the `swagger:` target in `proxy-router/Makefile` has to be run by hand, and the release build (`make build` → `build.sh`) never invokes `swag init`. Two CI jobs touch the file, and only one of them is advisory. The OpenAPI lint in `.github/workflows/docs.yml:74-77` downgrades its findings to a warning and blocks nothing. The `spec-fresh` job in `.github/workflows/proxy-router-ci.yml:210-233` blocks: it runs `scripts/check-spec-fresh.sh`, which lifts the real `swag init` line out of `make -n swagger`, regenerates into a scratch directory, and compares `docs.go`, `swagger.json` and `swagger.yaml` byte-for-byte, failing on any difference. That job is not gated by repository and runs on every branch and pull request, so a spec lagging the handler annotations fails CI rather than merging quietly. Where the spec and a handler do disagree, the handler is still authoritative. When you run the proxy-router locally, browse it at `http://localhost:8082/swagger/index.html`. For a curated subset of the most-used endpoints with prose context, see [API endpoints](/reference/api-endpoints).
