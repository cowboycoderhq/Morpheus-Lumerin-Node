The Linux release is a single **AppImage**. On first launch, the app downloads and manages its own services — proxy-router, `llama.cpp` AI runtime with the `Qwen2.5-1.5B-Instruct` demo model, and an IPFS node (kubo) as an optional service. For a source-build walk-through, see [macOS install (from source)](/consumers/install/macos) — the steps are nearly identical on Linux, but **the outcome is not**. This fork publishes no Linux proxy-router binary, so a from-source build installs cleanly and then hangs on the first-run wizard with no error (`ui-desktop/.env.example:57-64`). The AppImage above is unaffected: CI injects a real per-platform download URL. Read the caveat in the repo README before spending a build on it.

## Steps

<Steps>
  <Step title="Download">
    Grab the **latest** AppImage from [Releases](https://github.com/MorpheusAIs/Morpheus-Lumerin-Node/releases). The asset is named like `linux-x86_64-morpheus-app-<version>.AppImage` (use `linux-arm64-...` on ARM64, e.g. Raspberry Pi). Asset filenames carry a plain version and never a `-test` suffix — that suffix appears only on the release **tag** (`build.yml:283`).
  </Step>
  <Step title="Make executable and launch">
    Adjust the filename to the version you downloaded:
    ```bash
    chmod +x linux-x86_64-morpheus-app-*.AppImage
    ./linux-x86_64-morpheus-app-*.AppImage
    ```
  </Step>
  <Step title="Let the app fetch its services">
The first launch (and the first after each update) shows a setup wizard titled **Setting up your AI assistant** (`SetupWizard.tsx:293`, which replaced the older "Starting services" list): the app downloads the proxy-router, AI runtime, demo model, and an IPFS node (kubo) as an optional service, then starts them. Only the download of IPFS is tracked by the wizard — its **startup** is not a wizard phase; the network phase completes on the proxy-router alone and IPFS starts best-effort in the background, so an IPFS port conflict cannot freeze onboarding (`phases.ts:52-57`). **Container Runtime** (Docker) is not a user-facing phase in the wizard; it is started best-effort in the background after the proxy-router, alongside the other optional services (`orchestrator.ts:190`). It is **not** part of the readiness calculation — `calculateOrchestratorStatus()` reads only the proxy-router's download state and `requiredServicesRunning()` (`orchestrator.ts:684-703`). Docker availability is only detected, not required; the wizard does not display a card for Docker, so its absence never blocks onboarding.
  </Step>
  <Step title="Onboard">
    Accept terms, set a UI password, create or recover a wallet. Save the mnemonic somewhere safe.
  </Step>
  <Step title="Validate">
    Open `http://localhost:8082/swagger/index.html`. For Swagger **Try it out**, click **Authorize** and use the proxy-router `.cookie` credentials ([API auth](/reference/api-auth)). In Chat, click **New chat** and pick the model under the **Local** section to verify the pipeline.
  </Step>
</Steps>

## Cleanup

<Warning>
**Save your wallet mnemonic / private key first.** This deletes the local key store along with the downloaded services.
</Warning>

```bash
rm -rf ~/.config/morpheus-app
# Older builds may have used:
rm -rf ~/.config/MorpheusUI
```

(`morpheus-app` is the Electron package / `userData` folder name; the product name in the UI is **MorpheusUI**.)
